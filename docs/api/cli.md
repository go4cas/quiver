# quiver CLI

```
quiver routes [--dir <pages dir>] [--out <file>] [--watch]
quiver app [--src <source dir>] [--out <file>] [--watch]
```

For setups without the Vite or Bun plugin (an import-map app, another bundler, a test), `quiver app` writes the [app manifest](#quiver-app) that `quiver:app` would give you, and `quiver routes` writes the route manifest for a pages folder. The `quiver` binary comes with `@go4cas/quiver`.

How you run it depends on whether the package is installed:

| Setup | Command |
|---|---|
| `@go4cas/quiver` in `package.json` (after `bun install` / `npm install`) | `bunx quiver routes`, `npx quiver routes`, or `quiver routes` in a `package.json` script |
| no `node_modules` (a CDN/import-map app), Bun | `bunx --bun --package @go4cas/quiver@3 quiver routes` |
| no `node_modules`, npm | `npm exec --package=@go4cas/quiver@3 -- quiver routes` |

Without a local install, always name the scoped package: a bare `bunx quiver` or `npx quiver` downloads the unrelated npm package called `quiver`.

| Flag | Default | |
|---|---|---|
| `--dir` | `src/pages` | pages folder, relative to the current directory |
| `--out` | `src/routes.gen.js` | file to write, relative to the current directory |
| `--watch` | off | keep running and rewrite the file when a page is added, removed or renamed |
| `--help` | | print usage |

```bash
# with @go4cas/quiver installed
bunx quiver routes                     # src/pages → src/routes.gen.js
bunx quiver routes --watch             # and keep it up to date
bunx quiver routes --dir app/pages --out app/routes.gen.js
```

```js
import { initRouter } from '@go4cas/quiver'
import routes, { notFound } from './routes.gen.js'

await initRouter({ routes, notFound })
```

The output, for a folder with `index.js`, `users/[id].js` and `not-found.js`:

```js
// Generated by Quiver. Do not edit.
export default {
  '/': () => import('./pages/index.js'),
  '/users/:id': () => import('./pages/users/[id].js'),
}
export const notFound = () => import('./pages/not-found.js')
```

- Keys are sorted, specifiers are relative to `--out` (`./…` or `../…`), so the file is stable to commit. It is the same manifest the plugins generate.
- The file is written only when its content changes, so `--watch` doesn't touch it on every event. It is written to a temporary file next to it and renamed into place, so nothing ever reads half a manifest.
- Under `--watch`, scans run one at a time, and changes made during a scan trigger one more, so the file always ends up matching the folder. A scan error is printed, the last good manifest stays, and the watcher keeps running.
- Under `--watch`, a `--dir` that is missing or can't be read, or a watcher that fails later, prints one `[quiver] ` line and exits `1`.
- `--out` must not be a `.js` file inside `--dir`, since the scan would pick it up as a page; use a name starting with `_` there (`src/pages/_routes.gen.js`), or a path outside.
- An existing `--out` file is replaced only if it is empty or starts with `// Generated by Quiver.`, the first line of every manifest the CLI writes. Any other file is left as it is, with a `[quiver] ` error and exit `1`, so a mistyped `--out` can't overwrite your code. Files written by any 3.x release start with that line.
- Runs on Node 22.12+ and on Bun 1.4.4+.

| Exit code | Meaning |
|---|---|
| `0` | written or unchanged; also `--help` |
| `1` | scan error, messages on stderr, nothing written; `--out` exists and was not generated by Quiver; with `--watch`, a pages folder that is missing, unreadable or can no longer be watched |
| `2` | usage error (unknown command or flag, `--out` inside `--dir`); usage on stderr |

## quiver app

```
quiver app [--src <source dir>] [--out <file>] [--watch]
```

New in 3.2. Writes the [app manifest](./vite#quiver-app) for a source folder: routes from `<src>/pages`, plus `layouts/`, `middleware/` and `pages/**/_middleware.js`, `views/`, each page's `meta.nav`, and `app.config.js`. It is the module the plugins serve as `quiver:app`, for apps without Vite or Bun. Run it the same way as `quiver routes` (the table above).

| Flag | Default | |
|---|---|---|
| `--src` | `src` | source folder, relative to the current directory; pages are read from `<src>/pages` |
| `--out` | `<src>/app.gen.js` | file to write, relative to the current directory; not inside `pages/`, `layouts/`, `middleware/` or `views/`, and not `app.config.js` or a `_middleware.js` |
| `--watch` | off | keep running and rewrite the file when an app file is added, removed, renamed or edited (an edit can change a page's `meta.nav`) |

```bash
bunx quiver app                        # src → src/app.gen.js
bunx quiver app --watch
```

```js
import app from './app.gen.js'
```

- Specifiers are relative to `--out`, writes are atomic and only on change, an existing file is replaced only if Quiver generated it, and `--watch` keeps the last good file on a scan error, as for `quiver routes`.
- An `--out` that is one of the files the scan reads (`app.config.js`, a `_middleware.js`, a page, layout, middleware or view) is a usage error, with or without `--watch`, and nothing is written.
- Warnings (a `meta` it can't read, a misplaced `meta.nav`, an unknown `meta.layout`) go to stderr and the exit code stays `0`. Under `--watch`, a warning is printed when it first appears and not again while it stays. Scan errors exit `1`, and usage errors `2`.
- `--dir` belongs to `quiver routes` and `--src` to `quiver app`; passing one to the other is a usage error.
